# 公开信号扫描 workflow

这份文档定义「增长问题破局 PPT」里公开信号扫描页的通用生成流程。它适用于不同行业和公司，不绑定耐克案例。

## 目标

用公开信息先回答三个问题：

1. 发生了什么异常变化？
2. 这个变化的口径是什么？
3. 它可能指向什么增长问题？

这一页不是结论页，也不是用户交互页。它是报告里的证据页，负责把后续增长问题假设建立在可追溯的事实上。

## 输入

必填：

- 公司
- 行业
- 市场
- 时间范围
- 用户关心的问题

选填：

- 用户已有判断
- 内部补充信息
- 指定来源
- 竞品名单

## 来源优先级

公开信息按可信度从高到低使用：

1. 公司披露：年报、季报、公告、电话会、投资者日材料
2. 经营数据：收入、毛利、库存、渠道、门店、用户、订单、客单、ARPU、续费等
3. 行业数据：市场规模、增速、价格带、份额、品类迁移
4. 竞品证据：主要竞品财报、公告、门店、产品、价格、渠道动作
5. 渠道和用户信号：电商、App、社媒、搜索、招聘、门店观察
6. 权威媒体和专家访谈：用于解释和交叉验证，不能单独当硬事实

如果来源之间冲突，优先保留高等级来源，并在备注里标出冲突。

## 信号槽位

默认生成 6 张证据卡，优先覆盖以下槽位：

1. 增长结果：收入、订单、用户、GMV、客流是否承压
2. 渠道健康度：直营、经销、线上、线下、平台是否失衡
3. 产品或品类结构：哪些品类增长，哪些拖累
4. 价格和盈利质量：折扣、毛利、客单、ARPU、续费是否变化
5. 竞争生态位：本土竞品、新品牌、替代品是否挤压
6. 执行和组织信号：库存、供应链、门店、管理层动作、战略调整

不同行业可以替换槽位名称，但不能破坏三层信息结构。

## 卡片信息结构

每张卡必须有三层主信息：

```text
大数字：一眼抓住异常或机会，例如 -36%、+13.3%、100 家
指标说明：解释这个数字是什么指标、什么口径、什么时间段
战略解读：解释这个数字意味着什么，连接到增长问题
```

辅助字段：

- 信号标题
- 来源编号，例如 `〔S1/S2〕`
- 来源短名
- 可信度：高 / 中 / 待核实

禁止：

- 只写判断，不写数字口径
- 把媒体观点写成事实
- 没有来源编号就进入 PPT
- 在最终 PPT 里写「用户确认」

## 呈现顺序

默认顺序：

1. 先放增长结果异常
2. 再放渠道或收入结构异常
3. 再放产品/品类分化
4. 再放价格、盈利或品牌溢价变化
5. 再放竞争生态位变化
6. 最后放组织、执行或管理层动作

页面底部放「初步指向」，只写 2-4 个标签，例如：

- 渠道健康度
- 运动场景重构
- 本土化溢价

这些标签不是最终结论，只是下一步问题假设的入口。

## PPT 交付规则

最终交付必须是可编辑 PPTX，不是整页图片。

可编辑层：

- 标题、副标题、案例标签
- 每张卡的标题、来源编号、大数字、指标说明、战略解读、可信度
- 底部来源脚注
- 初步指向标签
- 卡片边框、分割线、图标和色块

图片层只允许用于：

- 可替换图标
- 可替换小插图
- 背景纹理或行业氛围图

禁止把整页证据墙导出成一张图片塞进 PPT。

## 输出

标准输出包括：

- `signal_cards`：6 张证据卡
- `source_register`：来源编号和 URL
- `initial_directions`：2-4 个初步指向
- `source_gaps`：待补证据
- `slide_spec`：可编辑 PPT 模板需要填入的字段

## 质量门

- 每个大数字必须有指标说明。
- 每个指标说明必须能回答「这个数字是什么」。
- 每个战略解读必须能回答「这个数字意味着什么」。
- 每张卡必须有来源编号。
- 媒体和专家访谈只能作为中等可信度来源，除非被公司披露或行业数据交叉验证。
- AI 可以提出假设，但必须和事实分开。
